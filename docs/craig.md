# Craig로 Discord 음성 녹음하기 (학습 데이터 수집용)

> 작성일: 2026-10-04 · 관련 문서: [goal.md](./goal.md)

## 1. Craig란

[Craig](https://craig.chat/)는 Discord 음성 채널을 녹음하는 무료 봇이다.
가장 큰 특징은 **말한 사람마다 오디오 파일을 따로 만들어준다**(멀티트랙)는 점이다.
그래서 여러 명이 대화한 채널에서도 **원하는 한 사람의 목소리 파일만** 골라 TTS 학습에 쓸 수 있다.

| 항목 | 무료 | 후원자 (월 1달러부터) |
|---|---|---|
| 1회 최대 녹음 시간 | 6시간 | 최대 24시간 |
| 파일 보관 기간 | 7일 | 최대 30일 |
| 화자 수 제한 | 없음 | 없음 |
| 자동 녹음 | X | O (Tier 2 이상) |
| 클라우드 자동 업로드 (Google Drive 등) | X | O |
| 자동 전사 (SRT, VTT, 텍스트) | X | O (Tier 3) |

## 2. 준비

### 2-1. 서버에 초대하기
1. https://craig.chat/ 에 접속해 **Add to Discord**를 누른다.
2. 초대할 서버를 고른다. 해당 서버의 관리 권한이 있어야 한다.
3. 봇에 필요한 권한은 **메시지 보내기, 연결, 별명 변경** 세 가지다.
   - **별명 변경 권한이 없으면 녹음이 되지 않는다.** Craig는 녹음 중일 때 자기 별명에 `[RECORDING]`을 붙여서 모두에게 녹음 사실을 알리기 때문이다.

### 2-2. 녹음 권한 설정 (선택)
- 다른 멤버도 녹음을 시작할 수 있게 하려면, 서버 관리 권한을 가진 사람이 접근 역할(access role)을 등록한다.
  ```
  /server-settings access-role add <역할>
  /server-settings view        # 현재 설정 확인
  ```

### 2-3. DM 허용
- 다운로드 링크는 **녹음을 시작한 사람에게 DM으로** 온다.
- 서버의 DM 수신이 꺼져 있으면 링크를 못 받는다. 이 경우 `/recordings` 명령으로 링크를 다시 볼 수 있다.

## 3. 녹음하기

```
/voice-test          # (권장) 녹음 전에 음질 테스트
/join                # 내가 들어가 있는 음성 채널 녹음 시작
/join channel:<채널>  # 특정 채널을 지정해 녹음
/note message:<메모>  # 현재 시점에 메모 남기기 (예: "대기실 잡담")
/stop                # 녹음 종료
/recordings          # 지난 녹음 목록과 다운로드 링크 보기
```

- 녹음 중에 Craig를 채널에서 내보내면 녹음이 종료된다.
- 녹음 패널 메시지를 지웠다면 `/join`으로 다시 띄울 수 있다.
- `/note`로 남긴 메모는 다운로드한 정보 파일과 Audacity 프로젝트의 라벨에 표시된다. 깨끗하게 녹음된 구간을 표시해 두면 나중에 찾기 쉽다.

## 4. 다운로드하기

1. DM으로 받은 링크(또는 `/recordings`)를 연다.
2. 형식을 고르면 서버에서 변환을 시작한다. 처리가 끝날 때까지 기다린 뒤 받는다.
3. **TTS 학습용 권장 설정**

| 선택 | 권장 | 이유 |
|---|---|---|
| 트랙 | **Multi-track** (기본값) | 화자별로 파일이 나뉨 |
| 형식 | **FLAC** | 무손실이라 Craig가 받은 음질 그대로임 |
| 피할 것 | WAV 직접 다운로드, AAC, Opus | Craig가 제공하는 WAV는 품질을 낮춘 버전임. AAC와 Opus는 손실 압축 |

4. 압축을 풀면 화자별 FLAC 파일이 나온다. 파일 이름에 사용자 이름이 들어 있으니 **학습 대상자의 파일만** 골라 쓴다.
5. 학습 도구가 WAV를 요구하면 직접 변환한다.
   ```bash
   # 모노, 24kHz WAV로 변환
   ffmpeg -i "1-username.flac" -ac 1 -ar 24000 target.wav
   ```

> 무료 버전은 **7일 뒤 삭제**되니 바로 받아 둔다. MP3로는 내보낼 수 없다.

## 5. 학습 데이터로 쓰기 전 주의사항

### 5-1. 음질 (Discord의 한계)
Craig는 Discord가 보내준 소리를 그대로 저장한다. 그래서 Discord에서 이미 손상된 음질은 되살릴 수 없다.
- Discord 음성은 Opus로 압축되어 전송된다.
- 노이즈 억제(Krisp)와 에코 제거가 켜져 있으면 목소리가 변형된다.

**음질을 높이려면 대상자에게 아래 설정을 부탁한다.**
- Discord 설정 → 음성 및 비디오 → 노이즈 억제 **끄기**, 에코 제거 **끄기**, 자동 게인 조절 **끄기**
- 서버 관리자는 음성 채널의 **비트레이트를 최대로** 올린다.
- 대상자는 **이어폰**을 쓴다. 스피커를 쓰면 다른 사람 목소리가 대상자 마이크로 섞여 들어간다.
- 가능하면 조용한 방에서 마이크와 일정한 거리를 유지한다.

> 최고 품질이 필요하면 대상자가 자기 컴퓨터에서 Audacity나 OBS로 **자기 마이크를 직접 녹음**하는 방법이 더 낫다 (goal.md 참고).

### 5-2. 그대로 쓸 수 없는 부분
대화 녹음에는 학습에 방해가 되는 구간이 많다. 실제로 쓸 수 있는 분량은 **녹음 시간의 일부**뿐이라고 보고 넉넉히 녹음한다.
- 웃음, 기침, "음..." 같은 소리
- 말끝이 흐려지거나 중간에 끊긴 문장
- 다른 사람 목소리가 섞여 들어간 구간

**이 프로젝트는 대본 없이 게임 중 대화만 쓴다.** 그래서 녹음 세션을 여러 번 쌓아 양으로 보완한다 (게임 음성의 특징은 [workflow.md](./workflow.md) 0장 참고).

### 5-3. 긴 대화 녹음은 어떻게 학습 데이터가 되나

**6시간 녹음을 사람이 처음부터 들으며 잘라서 텍스트를 붙이는 것이 아니다.** 자르기, 받아쓰기, 걸러내기는 스크립트가 자동으로 하고, 사람은 마지막에 **검수만** 한다.

```
대상자 트랙 (FLAC)
  ① 겹침 제거   ── 다른 사람 트랙에 소리가 있는 구간은 버림 (자동)
  ② 음성 검출   ── 말하지 않는 시간 제거 (Silero VAD, 자동)
  ③ 자르기      ── 3~15초 클립으로 (자동)
  ④ 필터링      ── 너무 짧거나, 잡음이 심하거나, 웃음·맞장구인 클립 제거 (자동)
  ⑤ 전사        ── Whisper로 텍스트와 신뢰도 생성 (자동)
  ⑥ 검수        ── 신뢰도가 낮은 클립 위주로 듣고 수정하거나 버림 (수동)
  → 학습용 JSONL / .list
```

**① 겹침 제거가 가능한 이유:** Craig의 화자별 파일은 모두 **같은 시간축으로 맞춰져 있다.** 그래서 대상자가 말하는 순간에 다른 사람 트랙에도 소리가 있는지 비교만 하면 된다. 말이 겹친 구간과 다른 사람 목소리가 새어 들어간 구간을 화자 분리 AI 없이 걸러낼 수 있다.

**⑥ 검수에 드는 노력**

| 방식 | 작업량 | 품질 |
|---|---|---|
| 전부 직접 교정 | 데이터 1시간당 수 시간 | 가장 좋음 |
| **신뢰도 낮은 것만 교정 + 일부 샘플 확인 (권장)** | 적당함 | 좋음 |
| 교정 없이 사용 | 없음 | 잘못 받아쓴 텍스트를 그대로 학습하므로 위험함 |

- Whisper가 주로 틀리는 것은 고유명사, 게임 용어, 은어, 웃음이 섞인 말이다.
- **애매한 클립은 고치기보다 버린다.** 데이터는 넉넉하다.

**남는 양 (추정):** 4명이 6시간 대화하면 대상자가 말한 시간은 약 1~1.5시간이다. 필터링을 거치면 **약 20~60분**이 남는다.
- GPT-SoVITS에는 충분하고, Qwen3-TTS에는 최소 수준이다.
- 대화 데이터로 학습하면 말투가 자연스러워지는 대신 낭독체는 약해진다.
- 게임 중 대화는 짧은 외침이 많아서 남는 비율이 더 낮다. **녹음 시간의 약 5~10%** 로 추정한다.

> 비슷한 일을 하는 공개 도구로 Amphion의 **Emilia-Pipe**가 있다 (실제 녹음을 TTS 학습 데이터로 바꾸는 파이프라인).
> 전체 작업 순서는 [workflow.md](./workflow.md)를 참고한다.

## 6. 동의 (필수)

- Craig는 녹음 중임을 표시하지만, 그것만으로 **AI 학습 동의**가 되지는 않는다.
- 학습 대상자에게 "**당신의 목소리로 TTS 모델을 만든다**"는 사실을 설명하고 명시적으로 동의를 받는다. 문자 메시지 등 기록이 남는 방식이 좋다.
- 대상자가 아닌 다른 참여자의 트랙은 쓰지 말고 삭제한다.

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 녹음이 시작되지 않음 | Craig에 **별명 변경** 권한이 없음. 역할 권한을 확인한다 |
| 다운로드 링크가 안 옴 | DM이 막혀 있음. `/recordings`로 링크를 확인한다. 다른 사람이 녹음을 시작했다면 링크는 그 사람에게 갔다 |
| 녹음이 갑자기 끊김 | 누군가 Craig를 채널에서 내보냈거나 Discord 연결 오류가 생김. `/join`으로 다시 시작한다 |
| 특정 사람 파일이 없음 | 그 사람이 녹음 중에 한 번도 말하지 않았거나(음소거) 녹음 시작 전에 나갔음 |
| 음질이 나쁨 | 5-1 설정을 확인하고, `/voice-test`로 미리 점검한다 |
