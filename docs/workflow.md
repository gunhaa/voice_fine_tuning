### 게임 음성 데이터의 특징

| 특징 | 영향 | 대응 (해당 단계) |
|---|---|---|
| 짧은 외침이 많음 ("힐!", "왼쪽!", "ㅋㅋ") | 쓸 수 있는 클립 비율이 낮음 | 3초 미만은 버림, 세션을 많이 쌓음 (2·4장) |
| 흥분해서 소리 지름 | 소리 깨짐(클리핑), 평소와 다른 음색 | 클리핑 클립은 버림 (4장) |
| 키보드·마우스 소리, 게임 소리 | 잡음이 같이 학습됨 | 이어폰 사용, 음질 점수로 필터링 (2·4장) |
| 게임 용어, 닉네임, 영어 섞임 | Whisper가 자주 틀림 | 용어 사전으로 Whisper에 힌트 제공, 검수 (1·4·5장) |
| 텍스트가 미리 없음 | 모든 클립을 자동 전사하고 검수해야 함 | 신뢰도가 낮은 순서로 검수 (5장) |

**결과물의 성격:** 낭독하는 목소리가 아니라 **"게임할 때 말하는 그 사람"의 말투와 텐션**이 학습된다. 대화형 TTS에는 장점이고, 차분한 낭독에는 약하다.

### 3070 (8GB)에서 할 수 있는 것

| 작업 | 3070 로컬 | 비고 |
|---|---|---|
| Whisper large-v3 전사 | ✅ | fp16 또는 int8 |
| Qwen3-TTS 추론 (0.6B·1.7B) | ✅ | 제로샷 기준선 생성 |
| GPT-SoVITS 학습 | ✅ | batch 1~2 |
| Qwen3-TTS 0.6B 학습 | ⚠️ 빠듯함 | 메모리 부족(OOM)이 나면 batch 1, 짧은 클립만 사용, 또는 클라우드로 |
| Qwen3-TTS 1.7B 학습 | ❌ | 클라우드 GPU (24GB 이상) |

## 2. 녹음 (Craig)

**평소처럼 게임하면서 녹음한다. 세션을 여러 번 쌓는 것이 핵심이다.**

| 목표 | 깨끗한 데이터 | 필요한 게임 녹음 (추정) |
|---|---|---|
| GPT-SoVITS 첫 결과 | 20분 | 약 4~6시간 (1~2세션) |
| Qwen3-TTS 학습 | 1시간 이상 | 약 10~20시간 |

> 게임 녹음에서 학습에 쓸 수 있는 양은 **전체 녹음 시간의 약 5~10%** 로 추정한다. 첫 세션을 처리해 본 뒤 이 비율을 실측해서 표를 고친다.

**좋은 세션의 조건:** 대화가 많은 게임(협동, 전략, 턴제) > 계속 외치는 게임(FPS 교전)이다. 대기실, 로딩 시간, 정비 시간의 잡담이 가장 깨끗한 데이터가 된다.

녹음 전 체크리스트
- [ ] 대상자: **이어폰(헤드셋) 필수**. 스피커를 쓰면 게임 소리와 다른 사람 목소리가 마이크로 들어간다
- [ ] 대상자: Discord 에코 제거와 자동 게인 조절 **끄기**
- [ ] 노이즈 억제: 조용한 환경이면 **끄기**, 키보드 소리가 크면 **켜기**. 처음 한 번은 두 방식으로 각각 10분씩 녹음해 비교한다
- [ ] 대상자: **눌러서 말하기(PTT) 대신 음성 감지** 모드를 쓴다 (PTT는 말의 앞뒤가 잘리기 쉽다)
- [ ] 마이크 입력 음량: 소리를 질러도 깨지지 않을 만큼 약간 낮게
- [ ] 서버 음성 채널 **비트레이트 최대**
- [ ] `/voice-test`로 음질 확인
- [ ] 녹음은 **데이터를 관리할 본인이 `/join`** (다운로드 링크가 본인 DM으로 오도록)
- [ ] 차분하게 대화하는 구간이 길어지면 `/note`로 표시해 둔다 (예: `/note 대기실 잡담`). 나중에 `ref.wav`를 고를 때 쓴다

## 4. 자동 처리 (스크립트, 세션당 약 30분)

이 단계의 목표는 **사람 손을 대지 않고** 녹음을 "클립 + 텍스트 후보"로 바꾸는 것이다.

| 순서 | 할 일 | 도구 | 기준값 (출발점) |
|---|---|---|---|
| 4-1 | 대상자 트랙을 48kHz 모노 WAV로 변환 | ffmpeg | 원본 샘플레이트 유지 |
| 4-2 | **겹침 제거**: 다른 사람 트랙에 소리가 있는 구간을 버림 | Silero VAD (트랙별) | 앞뒤 0.3초 여유 |
| 4-3 | 음성 구간 검출 후 자르기 | Silero VAD | 클립 길이 3~15초 |
| 4-4 | 자동 필터링 | 길이, 음량, DNSMOS | 3초 미만 버림 (짧은 외침 제거), 소리 깨짐(클리핑) 버림, 음질 점수 하위 20~30% 버림 (키보드·게임 소리) |
| 4-5 | 전사 | faster-whisper `large-v3`, `language="ko"` | `vocab.txt`의 용어를 `initial_prompt`/`hotwords`로 전달. 클립별 텍스트와 평균 신뢰도(avg_logprob) 저장 |
| 4-6 | 검수 시트 생성 | → `review.csv` | 열: 파일, 길이, 텍스트, 신뢰도, 상태 |

- Whisper는 아무 소리도 없거나 잡음뿐인 구간에서 **없는 말을 지어내는 경우**(예: "시청해 주셔서 감사합니다")가 있다. 이런 정형 문구와 같은 글자가 반복되는 결과는 자동으로 버린다.
- 클립 길이에 비해 글자 수가 지나치게 적거나 많으면(말 속도가 비정상적이면) 전사 오류일 가능성이 높으니 버린다.
- 3070에서 Whisper large-v3로 1시간 분량을 전사하는 데 **수 분~10분 정도** 걸릴 것으로 예상한다 (추정).

## 5. 검수 (사람, 데이터 1시간당 1~3시간)

`review.csv`를 **신뢰도가 낮은 순서로 정렬**해서 위에서부터 처리한다.

| 상태 | 기준 |
|---|---|
| `ok` | 들어보니 텍스트가 정확함 |
| `fix` | 한두 글자 틀림. 직접 수정 |
| `drop` | 웃음, 맞장구("ㅇㅇ", "아"), 비명·고함, 욕설만 있는 클립, 말이 겹침, 게임 소리·키보드 소리가 큼, 애매함 → **고치지 말고 버린다** |

- 신뢰도 하위 약 30%는 전부 듣는다. 나머지는 **무작위로 50개만** 들어 보고, 오류가 많으면 기준을 넓힌다.
- 숫자와 영어는 **읽은 그대로** 한글로 적는다 (예: "3시" → "세 시", "OK" → "오케이"). 학습 데이터 안에서 표기 방식을 하나로 통일하는 것이 중요하다.
- 게임 용어와 닉네임은 `vocab.txt`의 표기를 따른다. 발음대로 적을지 원어로 적을지 정하고, **처음부터 끝까지 같은 방식**을 쓴다.
- 끝나면 `ok`와 `fix` 클립만 `dataset/`으로 내보낸다. **10%는 test로 분리**한다.

**다음 단계로 넘어가는 기준:** 깨끗한 클립 합계 **20분 이상** (GPT-SoVITS 기준). Qwen3-TTS는 **1시간 이상**을 목표로 게임 세션을 계속 쌓는다. 새 세션은 3~5단계만 반복해서 `dataset/`에 추가한다.

## 6. 기준선 만들기 (30분)

학습하기 전에 **"학습 없이 얼마나 되는지"를 먼저 기록**한다. 이게 없으면 파인튜닝 효과를 판단할 수 없다.

- [ ] Qwen3-TTS 1.7B Base로 `ref.wav` 제로샷 클로닝 (3070에서 추론 가능)
- [ ] test 문장 10~20개를 생성해서 `eval/baseline/`에 저장

## 7. 학습

### A단계: GPT-SoVITS (3070 로컬, 1시간 이내)

- 데이터: `dataset/train.list` (`경로|화자|ko|텍스트`)
- 설정 출발점: batch 1~2, SoVITS 약 8 epoch, GPT 약 10 epoch
- 메모리 부족(OOM)이 나면 batch를 1로 줄이고 12초가 넘는 클립을 뺀다
- 결과로 test 문장을 생성해 `eval/gptsovits/`에 저장

### B단계: Qwen3-TTS (데이터 1시간 이상 모였을 때)

| 선택지 | 어디서 | 비용 / 시간 (추정) |
|---|---|---|
| 0.6B 학습 | 3070 로컬 (batch 1) | 무료 / 수 시간. 메모리 부족이 나면 아래 방법으로 |
| **1.7B 학습 (권장)** | 클라우드 24GB 이상 (RTX 4090, L4, A10G) 또는 A100 | 몇 달러 / 1~2시간 |

- 학습률은 **1e-5 이하**로 시작한다 (데이터가 적으면 높은 학습률이 화자 품질을 떨어뜨린다는 보고가 있음)
- 모든 줄의 `ref_audio`는 **같은 `ref.wav`** 를 쓴다
- 학습이 끝나면 체크포인트만 내려받아 **추론은 3070에서** 한다

## 8. 평가 (1시간)

| 방법 | 내용 |
|---|---|
| **블라인드 청취** (필수) | 기준선, A, B로 만든 음성을 섞어 놓고, 누가 만든 건지 모르는 상태에서 대상자 지인에게 "누가 가장 비슷한가" 묻기 |
| 발음 정확도 (선택) | 생성한 음성을 다시 Whisper로 받아써서 원문과 비교 (글자 오류율, CER) |
| 화자 유사도 (선택) | 화자 임베딩 모델로 원본과 생성 음성의 유사도 계산 |

**판단 기준**
- 기준선보다 낫다 → 완료. 데이터를 더 모아 B단계로 진행
- 기준선과 비슷하다 → 데이터의 양과 질 문제. 게임 세션을 더 쌓거나, 4장의 필터 기준을 엄격하게 바꾼다 (양보다 질)
- 잡음이나 게임 소리가 같이 나온다 → 음질 점수 필터를 강화하고, 해당 세션의 데이터를 뺀다
- 발음이 이상하다 → 전사 오류 문제. 5단계 검수를 다시 본다

## 9. 그래픽카드를 바꾸면

| GPU (VRAM) | 달라지는 점 |
|---|---|
| **3070 (8GB)** — 현재 | GPT-SoVITS 학습은 로컬, Qwen3-TTS 학습은 클라우드 |
| 3060 12GB / 4070 (12GB) | Qwen3-TTS 0.6B 학습을 로컬에서 안정적으로 |
| 4060 Ti 16GB / 4080 (16GB) | 위 항목 + batch를 키워 학습 속도 향상 |
| **3090 / 4090 (24GB)** | **Qwen3-TTS 1.7B 학습까지 로컬에서** (bf16, 작은 batch). 클라우드 불필요 |

- **업그레이드 우선순위: VRAM 용량 > 속도.** 같은 값이면 4070(12GB)보다 **중고 3090(24GB)**이 이 프로젝트에 더 맞다.
- 바꿔도 **1~6단계는 그대로**다. 7단계 B의 "어디서"만 달라진다.

## 10. 예상 일정 (처음 한 번)

| 주차 | 할 일 |
|---|---|
| 1주차 | 준비, 용어 사전 작성, 게임 녹음 1~2세션 (약 4~6시간) |
| 2주차 | 자동 처리 스크립트 작성, 검수, 기준선 만들기, **GPT-SoVITS 첫 결과** |
| 3주차 이후 | 게임할 때마다 녹음해서 3~5단계 반복 → 데이터 1시간 이상 (게임 녹음 약 10~20시간) → Qwen3-TTS 학습 → 평가 |

> 이 문서의 기준값(클립 길이, epoch, 필터 비율, 소요 시간)은 **출발점**이다. 첫 세션을 처리해 보고 조정한다.
